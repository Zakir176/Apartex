# Contributing to Apartex

First off, thank you for considering contributing to Apartex! It's people like you that make the open-source community such an amazing place to learn, inspire, and create.

## 🚀 How Can I Contribute?

### Reporting Bugs
- Use the GitHub Issue Tracker.
- Describe the bug in detail, including steps to reproduce.
- Mention your environment (OS, Browser, Python version, etc.).

### Suggesting Enhancements
- Check the [Roadmap](./docs/ROADMAP.md) first to see if it's already planned.
- Open an issue with the "enhancement" label.
- Provide a clear and concise description of the feature.

### Pull Requests
1. Fork the repository.
2. Create a new branch (`git checkout -b feature/amazing-feature`).
3. Commit your changes (`git commit -m 'Add some amazing feature'`).
4. Push to the branch (`git push origin feature/amazing-feature`).
5. Open a Pull Request.

---

## 🛠️ Development Setup

Refer to the READMEs in the `backend/` and `frontend/` directories for specific setup instructions.

### Coding Standards
- **Python**: Follow PEP 8 guidelines. Use type hints where possible.
- **JavaScript/Vue**: Follow the Vue.js style guide. Use Composition API.
- **CSS**: Prefer Vanilla CSS or Tailwind utility classes (if applicable). Use BEM naming for custom styles.

### Testing
- Ensure all tests pass before submitting a PR.
- Add new tests for any new features or bug fixes.
- Backend tests: `pytest`
- Frontend tests: `npm run test:unit` (if configured)

---

## 📝 Commit Messages
- Use clear and descriptive commit messages.
- Start with a verb (e.g., "Add", "Fix", "Update").
- Reference issues if applicable (e.g., "Fix #123").
